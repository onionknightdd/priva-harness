# DS Bot 多 Bot 团队控制（发言、文件、队友感知）

阅读修订：GitHub `Fei2411/DS-Bot` tag `v0.3.8`，commit `5e9b7da8882da3b68d8a0624342708c2150a9156`（2026-11-16，PR #1671 “release: v0.3.8”）。仓库描述为 “A team of long-lived bots for DeepSeek Harness”。下面的机制都对照这次检出的 `ds-bot/src/host/`，不引用 v0.1.0 teardown 或 ds-bot@0.1.7 博文（那些版本早于当前调度器；旧的 `relayLimit` / `lateRounds` 已在 `store.js` 标成 LEGACY 并删除）。

DeepSeek Harness 只用到 DS Bot 实际调用的那一层：每个 Bot 的身体是一条 DSH Session；群里每个成员另有一条 group Session；群自己还有一条只做转发的 Session。注入用 `createUserMessage`（`@deepseek-ai/dsh-llm`）加上 `agent.steer` / `agent.followup`。群的转发回合被 `llm/stream` 钩子换成合成的 `group_relay` 工具调用，不再问模型。

## 群聊里谁可以接着说，顺序是宿主强制还是只写在提示词里？

### Takeaway
下一句谁开口由宿主调度器 `openingCall` / `callIn` / `startable` / `runRound` 决定，模型不能靠无视提示词改顺序。`admin` 是新建群的默认：没有 `@` 的消息只叫管理员。`everyone` 让全体按管理员优先、一人说完或 [PASS] 后再叫下一人。`@Name` 并行开工；只有管理员的 `@all` 能在回合中途叫全员。`[PASS]`、4 分钟无活动、15 秒工具宽限、连续 6 次空转，都在代码里截断或改道，不是劝模型自觉。

### Cited Findings
- 新建群默认 `mode: mode ?? 'admin'`。常量注释写明：`everyone` 是每人轮流、管理员先说；`admin` 是普通消息只给管理员，由它用 `@` 叫人；没有管理员的群仍按 `everyone` 答。新群用 `admin`，因为每个额外发言者都要重读整段上下文。 — [constants.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/constants.js) `ROOM_MODES`；[roster.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/roster.js) `createRoom`；工具参数原文：`'"everyone": every member answers a plain message in turn, admin first. "admin" (the default): a plain message goes to the admin, who calls others with @Name. @mentions always choose who answers.'` — [tools.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/tools.js) `MODE_PARAM`
- 文件头说明宿主语义：一条消息里 `@` 到的成员同时开工；普通消息在 admin 模式只给管理员，否则全体轮流、管理员先、前一位 posted 或 passed 之后才叫下一位。用户自己的消息总会被回答。Bot 之间可以一直互叫，直到用户在群详情里停掉。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) 第 1–18 行
- `openingCall` 的选择顺序（宿主，不是提示词）：kickoff / goal 帖只叫管理员；`done` 只叫 `askedBy`；有具名 `@` 且不是 `@all` 就只叫那些人，`ordered: false`（并行）；否则若 `!all && mode === 'admin' && admin` 只叫管理员；再否则全体，管理员排第一，`ordered: !all && speakers.length > 1`。所以 `@all` 是并行叫全体，普通 everyone 消息是串行。 — 同文件 `openingCall`
- `@` 的词法在 `mentionSpans`：`ALL_WORDS = ['all', 'everyone', '所有人', '全体']`。代码块、行内码、Markdown 链接里的 `@` 不算呼叫。名字后面紧跟字母、数字、`_`、`-`、路径字符就不算（避免 `@Mi` 命中 `@MiniMax`，以及 DSH 把文件引用写成 `@docs/guide.md`）。 — [mentions.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/shared/mentions.js)
- 回合中途一条成员发言里的 `@all` 只有管理员能展开成全体：`callFrom` 写 `rt.isAdminOf(room, member.id) && all ? [...found, ...others] : found`，注释是 “only the admin, so a member cannot set off a storm”。非管理员只 `@all`、不点名，callee 列表为空，不会开新回合。这是宿主强制。开场帖走的是 `openingCall`，那里 `@all` 不查是不是管理员，用户或发帖 Bot 的 `@all` 会并行叫全体。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `callFrom`、`openingCall`
- 串行是调度器强制的。`startable`：slot 必须是 `waiting`，同一成员不能已经在本回合 `speaking`；`ordered` 的 slot 还要前面所有 ordered slot 既不是 `speaking` 也不是更早的 `waiting`。`runRound` 的循环只启动当前 `startable` 的 slot，一个 turn 结束、新呼叫进来、用户发话或回合被停，才 `nudge` 再扫一遍。同一时刻一个群只有一个 round；进行中到达的帖通过 `joinRound` 并进当前 round，否则进 `laterPosts` 等下一轮。 — 同文件 `startable`、`runRound`、`startRound`
- `[PASS]` 由宿主识别，不靠模型“保持沉默”的自觉。`isPass`：空串，或整段匹配 `[PASS]`、`【PASS】`、`(PASS)`、`pass`（可带句号）。回合中途的 step 若是 pass，`roomTurn` 的 `say` 直接 return，不写入群日志。最终回复若是 pass，slot 标成 `passed`（被 abort 则 `cancelled`，超时则 `missed`），pass 文本本身不进日志。管理员单独面对用户消息并且 passed、又没有人 posted/working/waiting-approval 时，宿主写一条 notice，原因 `admin-passed`，给成员看的句子是 “did not answer or call anyone; call a member with @Name.” — 同文件 `isPass`、`roomTurn`、`memberTurn`、`runRound`、`noticeText`
- 提示词里的 `[PASS]` 是发给成员模型的约定，和上面的识别配套。每回合用户消息末尾固定带 `ROOM_REPLY`：`Reply [PASS] to stay silent when you have nothing new to add or the message is for someone else.` 同段还要求：被要求做事时，开场说明和第一次工具调用必须在同一步，否则回合结束、工作不会跑。这后半句有宿主配合：`turns.js` 在“答应了要干活但没调工具”时用固定文本重试一次，其中写明 `If your last reply already was your whole answer, reply [PASS]; it stays posted.` — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `ROOM_REPLY`；[turns.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/turns.js) `RETRY_PROMISE_TEXT`
- 发言顺序也写进该成员这一跳的用户消息，但是说明，不是约束。`placeLines`：ordered 时写成 `Members answer this message one at a time: A → B → C` 和 `You are number N of M`；并行时写成 `Called together with you: … You answer at the same time and do not see each other's replies until they post.` 真正不让后一个人提前开工的是 `startable`。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `placeLines`
- 空转上限是宿主的，上限 6，不是旧文档里的 relay 次数帽。`ROOM_IDLE_RELAY_LIMIT = 6`。Bot 对 Bot 的一步如果没调用工具，且正文是致谢/待命/重复（`isIdleRelayText`，去掉 `@` 后长度 ≤ 45 且匹配 ack 或 status 词表，或与该成员本回合先前正文互相包含），`countIdleStep` 给 `room.idleRelays` 加一。达到 6 或已经 paused，`holdIdleCalls` 把本来要叫的人放进 `room.paused`（`idle: true`），并写 notice：来回 6 次没有进展，这些 `@` 等到用户在这里写字。用户消息（`drainRoomInbox` / `joinRound` / 开场 user post）调用 `unpauseRoomIdle` 并 `releaseParked`。用了工具或正文有新内容则 `clearIdleStreak`，但清的是计数，不会解开已经 pause 的房间。`store.js` 明确删掉旧字段 `relays`、`relayLimit`、`lateRounds`。 — [constants.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/constants.js)；[groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `isIdleRelayText`、`callFrom`、`holdIdleCalls`；[store.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/store.js)
- 两条和“等回复”有关的宿主时限：`ROOM_REPLY_TIMEOUT_MS = 240_000`，`roomTurn` 每次 Session 事件 `touch` 都重置；超时则 `{ missed: true }`，回合继续，并写 notice “did not answer within N minutes”。`ROOM_WORK_GRACE_MS = 15_000`：非团队快捷工具一开始，15 秒后该 slot 标 `working`，回合不再等它；收尾文字以后由 `lateRoomReply` 发回群里。团队工具名单 `TEAM_TOOLS` 不算“开始干活”。 — [constants.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/constants.js)；[groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `roomTurn`、`workRoomTurn`
- 群自己的 Session 不跑模型。`groups.js` 末尾 `llm/stream`：若这条 Session 是一个 room，且最后一条相关消息来自 user / schedule / Bot post / kickoff / goal，宿主直接 yield 一个合成 `group_relay` 工具调用（参数只有 `roundId`），`finish` reason 为 `tool-calls`。注释写明原因：模型会偏离 “only call group_relay”。工具执行里 `group_relay` 立刻 `concludeTurn`，真正的 round 在 DS Bot 进程里跑，不占着这次工具调用。群 Session 的 system prompt 仍注册了 relay 文案，但正常路径到不了模型。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `group_relay`、文件末尾 `llm/stream`；[prompt.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/prompt.js) `# Group chat relay`
- 成员发言是真模型回合。`roomTurn` → `rt.deliver` 把拼好的 transcript 送进该成员在这个群里的 Session。群 Session 只注册 `group_relay`（`relayOnly`）；成员的 group Session 才有全部 team tools。 — [tools.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/tools.js) `shareBotTools`

### Inferences
- “管理员先说、其他人等”在 everyone 模式是队列位置加 `startable`，模型即使在提示词里假装自己是下一位，宿主也不会给它投递，除非它被 `@` 或排到。
- 成员模型仍然可以在自己的回合里乱说话或乱 `@`。宿主会照它写出的 `@` 去叫人（受 admin-only `@all` 和 idle cap 约束），但不会改它已经生成的句子。`[PASS]` 只有在输出匹配 `isPass` 时才被当成沉默。
- 群聊费用优化（README 说默认由管理员回复）对应的就是默认 `admin` 模式加合成 relay，不是另一个调度器。

### Gaps
- 没有把 DSH 里 `agent.steer` / `followup` 的运行时源码再打开一遍；行为依据是 DS Bot 自己的注释和它在 `turns.js` 里对 Session 事件的记账。
- 没有对照 u1-lab teardown（v0.1.0）和 zayfen 博文（0.1.7）。当前 `idleRelays` 与已删除的 `relayLimit` 说明那两篇里的轮次帽不能当成 v0.3.8。

## 回合进行中又来一条消息，是改当前回合还是排队？注入格式是什么？

### Takeaway
分两条路径。用户在群 Session 里发的纯文本，若当前 round 还开着，宿主把它记进群日志并按 `openingCall` 在**同一 round** 里叫人，不另开一轮。已经在干活的成员收到的呼叫走 `agent.steer`：一条 user-role 消息，插进当前 turn 的下一步；这一 round 不等它，收尾后再用 `followup` 补一次 deferred 回合，专门用来回答这次呼叫。私聊里用户插话才会砍掉正在跑的模型调用；群 Session 不走那条 cut。

### Cited Findings
- 投递格式一律是 user message，不是 system reminder，也不是 tool result。`deliver` 调用 `createUserMessage`，正文是一行 header 加换行加正文：群回合 header 为 `[Group chat "${roomName}" · ${note}]`。`note` 来自呼叫，例如 `your turn`、`the user mentioned you`、`new message from the user`、`${name} mentioned you`。`source.kind` 为 `'bot'`（`SOURCE_KIND`），`form: 'relay'`，`role: 'room'`，并带 `exchangeId`、`roomId`、可选 `askedBy`。`steer === true` 时 `agent.steer(message)`，否则 `agent.followup(message)`。注释：steer 在当前 turn 的下一步切进去；follow-up 排到下一 turn。 — [delivery.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/delivery.js) `headerFor`、`deliver`
- 成员此刻已经有 turn 或 subagent 时，`roomTurn` 把 `steer: busy` 传给 `deliver`，然后立刻 `resolve({ working: true })`，round 继续。注释：呼叫会在下一步 steer 它。空闲则 follow-up，`roomWaiters` 等到该 turn 结束、失败、审批或超时。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `roomTurn`
- 这条 steer 进去的 room/request 消息，`turns.js` 记在 `entry.joined`，不把它当成当前 turn 的回复对象。注释原文：`A request that lands inside a running turn steers that work but is answered in a hidden turn of its own once the work is done, so the sender never gets the turn's text.` turn 结束后，对每个 joined request 再 `deliver` 一次，`deferred: true`，因此不再 steer。群呼叫的 header 变成 `[Group chat "…" · you read this call during your last task; answer it now]`（`note` 参数那句）。私聊 request 的 deferred header 是 `[Message from ${fromName} · you read it during your last task; answer it now]`。 — [turns.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/turns.js) `user/message` 分支与 turn 结束循环；[delivery.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/delivery.js) `headerFor`
- 用户在群里打的纯文本，round 还在跑时并进当前 round。`drainRoomInbox` 读群 Session inbox 的 `nextStep` 和 `nextTurn` 里 `source.kind === 'user'` 的消息；正文为空、带非 text block、或含 `dsh-session:`（引用对话）就停，这条和它后面的都留给下一轮。其余立刻 `say` 进日志，再 `openingCall` + `callIn`。带图片或引用的帖在 `joinRound` 里被标成 `own`，放进 `laterPosts`，本轮不吞。kickoff 轮不抽 inbox。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `waitingLines`、`drainRoomInbox`、`joinRound`
- 私聊用户插话会取消正在跑的模型调用；群不会。`steer.js` 开头：private chat 的 user steer 必须马上到达。`privateOf` 要求 `chatOwners` 有这条 Session 且 `groupOwners` 没有。只有这时才 `maybeCut`。群里的 steer 只走 `deliver` 的 `agent.steer`，不走这个 cut。 — [steer.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/steer.js)
- Bot 对 Bot 的 `message_bot` 在私聊里：`when: 'now'`（默认）且对方正在干活、又不是 `reply_to: 'user'`，则 `steer: true`；`when: 'queue'` 或 `reply_to: 'user'` 则 follow-up。工具说明原文：now 是下一步读到并能改道，干完再答；queue 是等当前工作结束，只用于无关的新任务；`reply_to "user"` 永远排队。群 Session 里的 `message_bot` 不走这条，而是 `callInGroup`：拼成 `@Name …` 再 `roomStepText`，等价于在群里写了一句 `@`。 — [tools.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/tools.js) `message_bot`、`callInGroup`
- 同一 turn 里，模型在工具之间写的群消息会立刻进群日志（`postStep` / `roomTurn.say`），不等最终回复。间隔小于 `ROOM_STEP_GAP_MS`（30 秒）的行会并成一条。这些中途行里的 `@` 通过 `callFrom` 马上 `callIn`。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `postStep`、`callFrom`；[constants.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/constants.js)

### Inferences
- “steer”在群里的意思是：当前 turn 的模型上下文会在下一步看到这条 user message，所以它能改道；但这次呼叫的正式答复是 turn 结束之后那条 deferred follow-up，避免把当前工作的正文误送给呼叫者。
- 用户在群输入框发纯文本，改的是**群 round 的呼叫集合**（同一轮里多叫几个人），不是把一句话 system-inject 进某个正在生成的 token 流。那个成员若正忙，它看到的仍是上面的 steer user message。

### Gaps
- 没有在 DSH 源码里确认 `agent.steer` 是取消当前 LLM HTTP 请求，还是只把消息放进 `inbox.nextStep`、等本次模型返回后再给模型看。DS Bot 对私聊另写了 cut；对群没有。因此不能声称群里的 steer 会打断已经发出的那次补全。
- `waitingLines` 遇到图片或会话引用就整段留给下一轮；没有再追 UI 把这类消息送进已运行 turn 的别的通道。

## 工作目录、权限预设、群私有文件夹和共享记忆怎么分开？一个 Bot 能读写另一个的工作区吗？

### Takeaway
目录选择是宿主状态，写在 Session 创建时的 cwd：群有 `room.workDir` 则本群所有成员的 group Session 都用它，否则用该成员在本群的 `memberDirs`，再否则用 Bot 自己的 `workDir`，最后是团队 workspace。权限预设是 DSH 的 `permissionPresets.set`，群预设盖过个人预设，只作用在该群的 Session。记忆按目录分开，读写由 `remember` / `forget` 拒绝。普通 Bot 之间没有文件沙箱：A 可以读 B 的工作目录，只要 DSH 预设允许它访问该路径。只有 private Bot 的文件夹和记忆会被 DS Bot 在工具执行前拒绝。

### Cited Findings
- 解析顺序写在 `workDirOf`：`room.workDir` 优先；否则若 `room.memberDirs` 有这个 botId（含显式 `null`，表示团队 workspace），用那个；否则 `bot.workDir`。`sessionFolder` 先信 DSH 报的 cwd（`workingDirectory.get` 或 `session.header.cwd`），没有才回落到 `workDirOf`。Session 的目录在创建时固定；以后改目录会把对话推进到新的 part。 — [folders.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/folders.js) 文件头、`workDirOf`、`sessionFolder`

## Bot 怎样知道自己的名字、角色、队友、群记忆和协作协议？哪些是稳定身份，哪些每回合重灌？

### Takeaway

## Bot 之间的 handoff 和 Goal 阶段怎样叫醒下一位？

### Takeaway
群内交活不是任务板。`@Name` 或群里的 `message_bot` 立刻 `callIn`，下一位的 group Session 收到一条 `[Group chat …]` user message，从而开 turn。同一批被叫的人做完后，若真的干了活又没有再 `@` 别人，宿主再 `callIn` 叫醒当初那个呼叫者。私聊 handoff 是 `state.works` 树：子结果到齐后 `deliver` 一条 `[Reply from …]`。Goal 不逐个去敲成员；阶段任务靠管理员在回复里 `@Name`。一轮结束且没人在干活时，宿主向群 Session `followup` 一条 `[Goal check]`，合成 relay 后只叫管理员。`group_todo` 不唤醒任何人。

### Cited Findings
- 群内一批呼叫记在 `state.roomBatches`：谁叫的（`by`）、还没结束的成员（`pending`）、是否真用过工具（`worked`）。成员 posted 且这批 `pending` 清空、`worked && !answered`（没有再 `@` 别人）时，`callIn(round, [caller], "<names> finished the work you asked for")`，并把结果行放进 caller slot 的 `finished`，`roomPrompt` 会写成 “Results of the work you asked for…”。重启后还欠着的 batch 由 `settleRoomBatches` 用一条 late post 唤醒。 — [groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `registerBatch`、`memberTurn` 末尾、`settleRoomBatches`
- 私聊交接是 `handoffs.js` 的 work 树，不是群 round。文件头：请求是一件 work；接收者转出去的部分挂在下面；全部回来之后答案才向上送；不许再 message 那个正在等你结果的 Bot。`turns.js` 在 turn 结束时 `finish`：若还在等子 work 就 `holdWork`，否则 `tellSender` → `deliver`，角色 `reply`，header `[Reply from ${fromName}]`。晚到的结果加前缀 `LATE_ANSWER`。 — [handoffs.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/handoffs.js)；[turns.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/turns.js) `finish`；[constants.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/constants.js) `LATE_ANSWER`

- Goal 状态在 `room.goal`。管理员职责写进每回合的 `<group_goal>` 块，不是单独的系统提示。`DUTY_ACTIVE` 要求：把当前阶段的任务用 `@Name` 交给成员；同消息里叫到的人一起开工；回来后对照 “done when” 再 `group_goal pass` 或 `rework`。成员看到的块只有自己的任务句：`Your task in it: … (not started|working|reported|done).` 管理员 `@` 某人时 `goalTaskWorking` 把任务标成 working；该成员 posted 后 `goalTaskReported`。 — [goals.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/goals.js) `goalBlock`、`DUTY_ACTIVE`、`memberLines`；[groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `callFrom`、`memberTurn`
- 空闲时叫醒管理员是宿主 follow-up，不是任务板。`goalDrive` 在 round 收尾调用：goal 必须 `active`、未 idle、有管理员、本轮有人说话、没有人还在 `workingInRoom`、没有未完成 batch、inbox 空。然后 `goal.nudges += 1`，`queueGoalRelay(room, 'nudge', '[Goal check]', 'DS Bot')`。那是对群 Session 的 `agent.followup(createUserMessage(...))`，`source.role === 'goal'`。`openingCall` 对任何 `opener.goal !== undefined` 只叫管理员。管理员的 prompt 末尾加 `NUDGE_LINE`：`Goal check from DS Bot: nothing is running… If you are waiting for the user, reply [PASS].` 管理员对这次 check 回了 [PASS]，或连续 `GOAL_IDLE_NUDGES = 2` 次没有进展（进展 = 用户发言，或非管理员成员 `worked`），goal 标 `idle`，不再 nudge，直到用户消息把计数清掉。成员工作比 round 活得久时，`goalSettled` 在 turn 结束再跑一次同样的检查。 — [goals.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/goals.js) `queueGoalRelay`、`goalDrive`、`goalSettled`、`NUDGE_LINE`；[groups.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/groups.js) `runRoundFrom` 末尾、`openingCall`；[turns.js](https://github.com/Fei2411/DS-Bot/blob/5e9b7da8882da3b68d8a0624342708c2150a9156/ds-bot/src/host/turns.js) 把 `role === 'goal'` 放进 `roomInbox`

### Inferences
- 叫醒下一位的统一机制是：往一条 Session 里 follow-up 或 steer 一条 user message，DSH 因此开始一个 turn。群成员被叫时那条 Session 是 `room.sessions[botId]`；Goal 空闲检查先叫醒群的 relay Session，再由合成 `group_relay` 只把管理员放进 round。
- 提示词里的 “when a member finishes work you gave it, you answer its result” 有宿主对应物（batch 清空后 `callIn`）。若成员只用了文本、没有工具，`worked` 仍为 false，这批不会因此叫醒呼叫者。这是代码门槛，不是提示词。
